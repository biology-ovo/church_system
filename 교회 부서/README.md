# 교회 부서 일정관리

Python 3.12 이상, 표준 라이브러리만 사용합니다. 계정·일정·잠금은 SQLite에 저장됩니다.

## 현재 임시 편집 모드

로그인 화면과 회원가입도 일시 중지했습니다(`login_enabled: false`).
모든 부서에서 로그인 없이 날짜를 선택하고 일정 추가·제목 수정·항목 저장을 사용할 수 있습니다.
기존 로그인 세션이 있어도 현재는 로그인하지 않은 임시 사용자로 처리합니다.
로그인 화면을 다시 사용하려면 사용자 요청 후 `login_enabled`를 `true`로 바꾸고 재시작하세요.

전용 서버 없이 HTML 파일을 직접 열거나 정적 서버에서 실행해도 임시 일정 기능을 사용할 수 있습니다.
이 경우 현재 브라우저에만 저장되고 서버 데이터 및 다른 기기와 공유되지 않습니다.
서버 연결이 실패한 상황을 임의로 로컬 저장으로 바꾸지는 않습니다. 계정 API가 없는 정적 실행인 경우에만 로컬 저장을 사용합니다.

관리자 관련 기능도 모두 일시 중지했습니다(`admin_suspended: true`).
기존 관리자 계정으로 로그인해도 현재는 회원으로만 표시하며 관리자 권한을 제공하지 않습니다.
잠금·해제 버튼과 최초 입력자 정보는 표시하지 않고, 관리자 추가·지정 명령도 일시 중지했습니다.
계정·기존 권한·잠금 데이터는 삭제하지 않습니다.
사용자가 관리 체계 재개를 요청하면 `admin_suspended`와 `temporary_open`을 모두 `false`로 바꾸고 재시작합니다.

사용자 요청에 따라 `settings.json`의 `temporary_open`을 `true`로 설정했습니다.
현재는 로그인 없이 일정 추가·제목 수정·항목 저장이 가능하며 잠금 버튼은 표시하지 않습니다.
기존 최초 입력자와 잠금 정보는 보존하지만 임시 모드에서는 잠긴 항목도 수정할 수 있습니다.
임시 모드에서 새로 작성한 항목은 최초 입력자를 지정하지 않습니다.
관리자 체계로 복귀하려면 이 설정을 `false`로 바꾸고 서버를 재시작하세요.
관리 기능 중지를 해제한 뒤에는 `python3 server.py --require-login`으로도 로그인과 잠금을 다시 강제할 수 있습니다.
복귀 후에는 기존 잠금이 다시 적용되고, 최초 입력자가 없는 항목은 처음 저장하는 로그인 계정에 귀속됩니다.

## 실행 및 계정 준비

클라우드 작업 디렉터리는 `/workspace/church_system/교회 부서`입니다.

```sh
python3 server.py --reserve-admin ash3162 --reserve-admin siontennis
python3 server.py --create-user ash3162
python3 server.py --create-user siontennis
python3 server.py --create-user 일반사용자아이디
python3 server.py
```

계정 생성 명령은 비밀번호를 터미널에서 숨김 입력으로 두 번 받습니다(12자 이상).
임시 편집 모드에서 요청된 짧은 임시 비밀번호를 등록할 때만 `--temporary-password`를 함께 사용합니다(4자 이상).
예약된 관리자 계정은 비밀번호를 설정하기 전에는 로그인할 수 없습니다.
일반 사용자는 로그인 창 아래의 회원가입 탭에서 아이디·비밀번호·비밀번호 확인을 입력해 가입할 수 있습니다.
임시 편집 모드에서도 회원가입과 선택적 로그인·로그아웃을 사용할 수 있습니다.
회원가입으로 관리자 권한을 얻거나 기존·예약 관리자 계정을 덮어쓸 수 없습니다.
일반 사용자 계정을 서버 운영자가 명령으로 생성하는 방법도 유지합니다.
추가 관리자는 `python3 server.py --set-admin 기존아이디`로 지정합니다.
기존 계정의 비밀번호를 덮어쓰는 명령은 제공하지 않습니다.

개인 컴퓨터에서는 압축을 풀고 `교회 부서` 폴더에서 아래 명령을 실행하세요.
Python 3.12 이상이 필요하며 별도 패키지는 설치하지 않습니다.

```sh
python3 server.py --db "../교회 부서 데이터/schedules.sqlite3"
```

Windows에서는 `python3` 대신 `py`를 사용할 수 있습니다.
실행 후 브라우저 주소창에 `http://127.0.0.1:8001`을 입력합니다.
압축 파일에는 앱 소스만 포함되며 클라우드 계정·일정 데이터베이스는 포함되지 않습니다.
개인 컴퓨터에서는 회원가입으로 계정을 새로 등록할 수 있습니다.

서버는 기본적으로 루프백의 8001 포트에서 앱을 제공합니다.
`python3 -m http.server` 대신 이 전용 서버를 실행해야 로그인과 잠금이 작동합니다.
외부 서비스로 배포할 때는 HTTPS 역방향 프록시와 `--secure-cookies`를 사용하세요.
이 Python 서버는 개발용이며 운영 배포와 공개 주소는 아직 설정하지 않았습니다.

기본 DB는 체크아웃 밖 `/workspace/church-system-data/schedules.sqlite3`입니다.
`--db 경로`로 변경할 수 있습니다. DB와 백업에는 비밀번호 해시와 일정 데이터가 있으므로 공개하지 마세요.
기존 브라우저 localStorage 데이터는 삭제하지 않으며, 작성자를 확인할 수 없어 자동으로 가져오지 않습니다.

## 잠금 규칙

- 날짜를 선택하면 일정 목록과 **일정 추가**가 표시됩니다. 일정 추가를 누를 때마다 별도 일정이 생성되고 입력 항목이 열립니다.
- 같은 날짜에 여러 일정을 만들 수 있습니다. 목록에서 기존 일정을 눌러 다시 열 수 있습니다.
- 일정 제목은 1~100자로 수정하고 **제목 저장**을 누릅니다. 날짜는 목록의 기준으로 유지됩니다.
- 각 일정의 입력 값, 최초 입력자, 잠금은 서로 독립적입니다.
- 기존 서버의 날짜별 입력은 시작 시 **기존 일정**으로 한 번만 옮깁니다. 값·최초 입력자·잠금·버전은 유지하고 원본 테이블도 보존합니다.
- 부서·날짜·일정·항목마다 최초의 빈칸이 아닌 내용을 **저장**한 계정이 최초 입력자로 고정됩니다.
- 잠기기 전에는 로그인한 사용자들이 내용을 수정할 수 있습니다.
- 최초 입력자만 항목을 잠글 수 있습니다. 내용을 지워도 최초 입력자는 바뀌지 않습니다.
- 잠긴 동안에는 관리자도 바로 수정할 수 없습니다. 먼저 해제해야 합니다.
- 관리자 또는 그 잠금을 건 계정만 해제할 수 있습니다.
- 모든 권한 검사는 서버에서 실행합니다. 클라이언트가 보낸 역할이나 작성자 정보는 사용하지 않습니다.
- 변경 버전이 다른 요청은 거절합니다. 충돌하면 최신 내용 불러오기로 확인한 후 다시 입력하세요.
- 입력 후 각 항목의 저장 버튼을 눌러야 합니다. 저장하지 않은 입력은 화면 이동으로 사라질 수 있습니다.

```sh
python3 -m unittest -v test_server.py
```

잠긴 내용 변경 거부, 작성자 위조 거부, 동시 변경 충돌과 날짜·부서별 분리를 검사합니다.
